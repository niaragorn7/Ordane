# V1 — Order Management Core

## Goal

Build the core B2B quote-to-order workflow with Salesforce as the business application and Ordane as the domain authority for operational processing.

## Scope

- Customer and Opportunity management in Salesforce
- Quote creation and approval workflow
- Quote Items with products and quantities
- Optional pricing before AWS processing
- Salesforce → Ordane → AWS integration
- AWS pricing and availability processing
- Order generation from an Accepted Quote
- Order lifecycle and status transitions
- Go REST API
- PostgreSQL persistence
- UUIDv7 identifiers
- Basic automated tests

## Domain Model

```text
Customer
  └── Opportunity
        └── Quote
              └── QuoteItem ── Product

Quote ── 1:1 ── Order
                  └── OrderItem ── Product
```

Ordane uses UUIDv7 identifiers for its domain entities.

Salesforce-owned records such as Customer, Opportunity, and Quote retain their Salesforce IDs as external references for synchronization.

## Ownership

### Salesforce

- Customer and Opportunity management
- Quote user interface
- Quote approval workflow
- User-facing status representation

### Ordane

- Operational quote representation
- Order domain
- Order lifecycle
- Domain rules and invariants
- PostgreSQL persistence

### AWS

- Pricing
- Availability checks
- Order processing

Salesforce does not communicate directly with AWS.

## Integration Flow

```text
Salesforce
    │
    │ Quote / Order request
    ▼
Ordane API
    │
    │ Processing request
    ▼
AWS
    │
    │ Result
    ▼
Ordane API
    │
    │ Result / status
    ▼
Salesforce
```

## Quote Lifecycle

```text
Draft
  │
  ▼
Pending Approval
  ├──────────────► Rejected ──► Draft
  │
  ▼
Approved
  │
  ▼
AWS Pricing + Availability
  ├──────────────► Rejected
  │
  ▼
Accepted
```

Approval concerns the requested products and quantities. Final pricing is provided by AWS and is not part of the approval decision.

## Order Lifecycle

```text
Draft
  │
  ▼
Submitted
  ├──────────────► Failed ──► Submitted
  │
  ▼
Confirmed
  │
  ▼
Completed
```

An Order can only be created from an Accepted Quote.

## Quote Revision

When an Accepted Quote is revised while an active Order exists:

```text
Accepted Quote
      │
      ▼
Cancel active Order
      │
      ▼
Revise Quote
      │
      ▼
Approval
      │
      ▼
AWS Pricing + Availability
      │
      ▼
Accepted
      │
      ▼
New Order
```

## Core Invariants

- A Quote must contain at least one QuoteItem.
- A QuoteItem references exactly one Product.
- An Accepted Quote can have at most one active Order.
- An Order must contain at least one OrderItem.
- Order quantities must match the accepted Quote quantities in V1.
- Invalid status transitions must be rejected.
- Completed and Cancelled Orders cannot transition to another status.
- Quote revisions must re-enter the approval and AWS processing flow.
- An Order can only be generated from an Accepted Quote.

## Pricing

Pricing is intentionally simplified in V1.

- QuoteItems can initially have no price.
- Salesforce approval does not depend on final pricing.
- AWS determines the applicable pricing.
- `QuoteItem.unit_price` is populated when pricing is returned.
- `Quote.total_price` is calculated from the priced QuoteItems.
- Price lists and advanced pricing logic are deferred to V2.

## Out of Scope

- Advanced pricing and price lists
- Partial orders
- Multiple concurrent Orders per Quote
- Inventory management
- Automated approval workflows
- Async processing
- Analytics
- Mobile application
- Machine learning / AI
- Advanced observability and resilience
- AWS production deployment

## Definition of Done

- Salesforce can create and approve a Quote.
- An Approved Quote can be submitted to Ordane.
- Ordane can process the Quote through AWS.
- AWS can return pricing and availability results.
- Salesforce can receive the result and reflect Accepted or Rejected status.
- An Accepted Quote can generate an Order.
- An Order can progress through its defined lifecycle.
- Core domain rules and status transitions are tested.
- Data persists correctly in PostgreSQL.
- The Go API runs locally and can be exercised through standard HTTP tooling.
